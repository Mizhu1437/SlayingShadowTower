## 二、每个决策的架构后果（重要）

这一节是本文档的核心。决策本身只是一句话，但**它决定了代码怎么写**。以下每条都必须在实现时遵守，否则后期无法回退。

### 2.1 编辑器砍掉 → 但「一切内容皆数据」不能砍

砍掉的是**编辑器的界面**，不是数据驱动架构。

**必须保留：**
- 所有内容（卡牌、子弹、敌人、符卡、关卡波次、难度参数）仍为 JSON
- `content_loader` 仍带 schema 校验：JSON 写错时给出明确报错，而不是静默失败
- 数据格式文档化在 `docs/DESIGN.md`

**理由：** 数据驱动本身是「课程知识与理解」的素材（概念 #7），且是后期接编辑器或接社区内容的唯一前提。如果图省事把卡牌效果写成硬编码 if-else，将来任何平衡调整都要改代码。

**删掉的东西：**
- 任何 `editor/` 目录及其 UI
- 「不续关打通 N 解锁创意工坊」整套解锁链路（连存档字段都不需要）
- 原先设想的「Easy 通关解锁编辑器」保底机制（已无意义）

### 2.2 后期补像素美术 → 渲染层必须可换

现在用程序生成纯色几何图形，但**渲染必须走图集（atlas）路径**，不能把「画一个圆」写死在逻辑里。

**必须保留：**
- 子弹类型用字符串 id 标识（如 `rice_blue`），渲染层按 id 查贴图
- 缺图时回退到几何图形占位，不崩溃
- 贴图尺寸、判定半径分离：**判定半径由核心层数据决定，与贴图大小无关**

**理由：** 后期换图只替换贴图资源，不动核心。判定与视觉分离也是 STG 的基本正确性——东方正作的判定点远小于贴图，这不是美术问题而是玩法问题。

**顺带的收益：** 素材来源表在 MVP 阶段可以诚实地写「全部程序生成，无外部素材」，合规成本为零。

### 2.3 内容量 20 张卡 → 均衡比数量重要

**建议配比（可调，但总数不超过 20）：**

| 类型 | 数量 | 用途 |
| :--- | ---: | :--- |
| 被动卡 · 火力向 | 6 | 直接改伤害/射速/弹数/穿透 |
| 被动卡 · 特性向 | 6 | 追踪/范围/吸血/擦弹/暴击/位移加成 |
| 主动卡 · 输出向 | 4 | 高伤单体、清屏、范围弹幕 |
| 主动卡 · 功能向 | 4 | 回血、回能量、抽牌、护盾 |

**硬要求：至少 3 组可被玩家察觉的协同。** 例如：
- 「双发 + 追踪」→ 火力覆盖明显变宽
- 「穿透 + 高伤低频」→ 打 BOSS 单体显著变强
- 「擦弹回能 + 高耗主动卡」→ 构成风险回报循环

没有协同的 20 张卡等于 20 个孤立数值，肉鸽系统就白做了。这也是「创新与实用价值」那 10 分的落点。

### 2.4 世界观已定稿 → 命名仍用占位

**世界观已于 2026-10-26 定稿**，见 [WORLD.md](WORLD.md)。黑幕为渡里贝子。

核心层（弹幕、卡牌、碰撞、RNG）与世界观**完全解耦**，因此仍可并行。

**做法：**
- 卡名、关卡名先使用占位命名（如 `被动卡-01`、`Act1`）
- 占位名集中存放在 JSON 的 `name` / `displayName` 字段，**改名只需改 JSON，不动代码**

**仍待用户提供（不阻塞 P0–P3）：**

| 项 | 占位 | 最晚决定 |
| :--- | :--- | :--- |
| 自机是谁 | `自机` | P4 内容阶段前 |
| 卡牌通称 | `符片` | P4 内容阶段前 |
| 第二幕 BOSS | `Boss_Act2` | P3 流程阶段前 |
| 异变名称 | 暂空 | P5 文档阶段前 |

### 6.1 缺口处理顺序（按此顺序裁剪，不要跳序）

> **用户当前决定：先做完整体，时间不够再裁。以下为预留的裁剪顺序。**

| # | 裁剪项 | 省下 | 损失 |
| :---: | :--- | :---: | :--- |
| **1** | 前三幕关底 BOSS 符卡 3 → 2 张（贝子保留 5 张） | 约 1–1.5 周 | 前三幕 BOSS 稍单薄（它们本来就是剧情战） |
| **2** | 第四幕道中砍掉，只留「商店 → 贝子」 | 约 2 天 | 第四幕开局略显突兀 |
| **3** | 卡池 26 → 20 张 | 约 1 周 | 构筑变化减少 |
| **4** | 关卡生成器改为固定波次表（不随机） | 约 1.5–2 天 | 失去肉鸽随机性，但保留卡牌随机 |
| **5** | 第三幕与第二幕合并（四幕 → 三幕） | 约 2 周 | 单局时长回落到约 13 分钟 |

**第 1 刀是最划算的**：省时最多，损失最小。

### 6.2 三个硬前提（缺一必超期）

| # | 前提 | 不满足的后果 |
| :---: | :--- | :--- |
| 1 | **道中素材复用**：四幕共用同一套敌人与弹幕库，只换编排与配色 | 内容量 ×4，必超期 |
| 2 | **波次由生成器产出**，不手写 4 × 12 波 | 手写波次表 = 内容量 ×4 |
| 3 | **BOSS 弹幕复用**：第二、三幕 BOSS 沿用既有 pattern | 多造两个全新 BOSS |

> **若某条前提不成立，立即启用第 6.1 节的裁剪顺序，不要硬撑。**
