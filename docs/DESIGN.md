## 一、键位

| 键 | 功能 | 说明 |
| :--- | :--- | :--- |
| **方向键 / WASD** | 移动 | 待定，见下方待确认 |
| **Shift** | 低速移动（显示判定点） | 东方标准，**不承载其他功能** |
| **Z** | 打出选中的主动卡 | 原射击键让给卡牌 |
| **C** | 切换选中的卡（循环） | |
| **Esc** | 暂停 | |
| **Enter** | 确认 / 继续对话 | |

### 1.1 硬约束

> **Shift 只用于低速，绝不承载其他功能。**

理由：Shift 是弹幕游戏中最高频的精确移动键。把任何"切换/选择"类操作放到 Shift 上，会导致玩家每次操作都被强制减速，在弹幕中造成操作冲突。这是设计禁忌。

### 1.2 已取消的功能

| 取消项 | 理由 |
| :--- | :--- |
| ~~主动开火（按住 Z 射击）~~ | 先改为自动射击，**后又彻底移除**（见 1.3） |
| **自动射击（2026-10-26 移除）** | **所有输出只能通过卡牌实现。** 这是本作与传统 STG 最根本的分野：不再有"背景输出"，玩家的每一次伤害都来自一次主动选择 |
| **P 点（Power 道具）** | 火力成长完全由符片决定。若再加 P 点，等于两套成长系统争夺同一件事。砍掉后成长有唯一来源 |

### 1.3 彻底移除射击：这一决定的完整含义

> **本作没有自动射击，也没有手动射击。自机不发射任何子弹。**
> **全部伤害来自打出的卡牌。**

| 项 | 说明 |
| :--- | :--- |
| **玩家唯一的手部动作** | 移动、低速、C 切换、**Z 出牌**、X 符卡 |
| **伤害来源** | 100% 来自卡牌的 `damage_all` 等效果 |
| **DPS 曲线** | 完全由"抽到什么牌 + 能量够不够"决定，**波动极大** |
| **被动卡改造对象** | 不再是"自机射击形态"，而是**卡牌威力**（见 `Deck.resolveCardPower`） |

**为什么这么做：**

1. **让"选择"成为唯一的输出方式** —— 传统 STG 里射击是零决策动作，本作把它彻底去掉后，玩家想造成伤害就**必须**做决策。
2. **与「淘汰 P 点」是同一套逻辑** —— 火力成长只能来自符片，那自机本身就不该有输出。
3. **强化世界观** —— 灵力无型，不自带伤害；**符片是唯一的「型」**，也就是唯一的伤害来源。

**连带影响（已处理）：**

| 项 | 变化 |
| :--- | :--- |
| 被动卡词条 | `damage` / `interval` 不再改射击，改为折算成**卡牌伤害倍率**与**能量优惠** |
| `Shooter` / `ShotProfile` | 核心逻辑不再使用（文件保留，可能用于将来的射击类卡牌效果） |
| 敌人击杀 | 必须靠出牌，P1 时代的"自动清怪"不再存在 |
| 平衡 | 初始卡组必须有足够的伤害卡，否则玩家无法推进 |

**必须处理的玩家预期：**

> 东方玩家会本能以为自机在射击。**开局必须在 UI 上明示「本作没有自动射击」**，
> 否则玩家会长时间疑惑"为什么打不到敌人"。

## 二、手牌系统

### 2.1 参数

| 参数 | 值 | 符号 |
| :--- | :---: | :---: |
| 初始手牌 | **3** | S |
| 手牌上限 | **6** | U |
| 抽牌间隔 | **T = 5.0s**（全难度固定） | T |
| 本次抽牌的张数 | **D**（自动抽为 1，卡牌效果抽 N 张） | D |

### 2.2 规则（实现必须与此完全一致）

```
抽牌事件触发时（每 T 秒的自动抽牌，或卡牌效果触发的抽牌）：

  若 手牌数 >= U（即 6）：
      ── 触发「过载」
      ├─ 弃置全部手牌 → 进入弃牌堆
      ├─ 重抽 R = min(S + D, U) 张    ← 初始手牌数 + 本次应抽张数，上限为 U
      └─ 停止抽牌 (T × R) 秒
  否则：
      └─ 抽 min(D, U − 手牌数) 张
```

### 2.3 关键点：重抽量含本次抽牌数

> **过载时抽的不是固定的 S 张，而是「S + D」，且总和不超过 U。**

例（S=3, U=6, D=1）：

```
手牌 6 张 → 触发自动抽 1 张 → 满手，过载
  ├─ 弃置全部 6 张
  ├─ 重抽 min(3+1, 6) = 4 张
  └─ 停顿 4 × T 秒
```

**这个设计的好处：过载不会"吞掉"触发它的那次抽牌。** 玩家本该抽到的 1 张，被并入了重抽里——**所以过载不会让玩家少抽牌。**

若卡牌效果触发抽 3 张而手牌已满：

```
手牌 6 张 → 卡牌效果抽 3 张 → 过载
  ├─ 弃置全部
  ├─ 重抽 min(3+3, 6) = 6 张
  └─ 停顿 6 × T 秒
```

### 2.4 硬约束：禁止任何状态标记

> **不得加入"过载后需先打出一张才能再次过载"之类的标记位。**

**为什么**：会导致死锁。若玩家攒满 6 张后一直不出牌：
- 第 1 次过载：弃 6 抽 4，标记「已过载」
- 之后：抽到 6 张想再过载 → 被标记拦住
- **结果：手牌永远卡在 6 张，抽牌全部无效，机制彻底失效**

**规则必须无状态。** 上面那段伪代码就是全部逻辑，不需要任何额外变量。

### 2.5 停顿时长：S × T（最终定稿）

> **本节的公式经历两次修正，最终版如下。**

```
重抽量 R   = min(S + 溢出张数, U)
停顿       = S × T
```

**为什么是 S × T：**

过载由一次抽牌事件触发。重抽 R 张，相比"正常装下的那部分"，
净多赚 **S 张**（未截断时）。赚了 S 张，就跳过 S 个抽牌名额来抵消，
所以停顿 = **S × T**。

**关键性质：这个公式与本次抽牌数 D 无关。**

| D | 溢出 | R | 停顿 |
| ---: | ---: | ---: | ---: |
| 1 | 1 | 4 | S×T = 9s |
| 3（手牌 4 时） | 1 | 4 | S×T = 9s |
| 3（手牌 6 时） | 3 | 6 | S×T = 9s |

**修正历史：**

| 版本 | 公式 | 问题 |
| :--- | :--- | :--- |
| 初版 | R × T | 每次过载净亏 1 张（1200 秒模拟差值线性增长） |
| 二版 | (R-1) × T | D=1 时正确，但 D>1 时停顿过长，过载变成惩罚 |
| **定稿** | **S × T** | **与 D 无关，通用正确** |

**实测验证（1800 秒，D=1）：**

| 玩法 | 抽牌总数 |
| :--- | ---: |
| 憋牌不出 | 601 |
| 正常出牌 | 600 |

**差 1 张，属模拟相位误差，中性成立。**

### 2.5b 卡牌抽牌是纯收益（不是中性）

自动抽牌 D=1 时过载中性。但**卡牌效果抽牌是净赚的**：

| D | 1800 秒抽牌总量 | 相对 D=1 |
| ---: | ---: | ---: |
| 1 | 601 | — |
| 2 | 801 | **+33%** |
| 3 | 903 | **+50%** |

**这是有意的设计：** 抽牌卡是真收益，值得为它花能量。

### 2.5c 溢出才触发过载（手牌未满时）

> **手牌未满、但装不下本次抽牌时，只把溢出部分计入过载。**

```
例：手牌 4 张，卡牌效果抽 3 张
  ├─ space = 6 - 4 = 2，先装下 2 张
  ├─ 溢出 = 3 - 2 = 1 张
  ├─ 过载：弃全部，重抽 min(S + 1, U) = min(4, 6) = 4 张
  └─ 本次共得 2 + 4 = 6 张，停顿 S × T = 9s
```

**为什么不直接判满手过载：** 那样会让"手牌 4 张时抽 3 张"和"手牌 6 张时抽 3 张"
得到完全相同的结果，抹掉了溢出量的差异。**溢出越少，重抽越少**，这样才合理。

**R 被完全约掉。** 这不是"参数凑巧配平"，而是**结构性的**：

> 不论 S、U、D、T 取什么值，过载那一瞬间的抽牌速率永远等于 1/T。

验算多组参数：

| S | U | D | 重抽 R | 停顿 | 速率 |
| ---: | ---: | ---: | ---: | ---: | :---: |
| 3 | 6 | 1 | 4 | 4T | 1/T ✅ |
| 3 | 6 | 3 | 6 | 6T | 1/T ✅ |
| 3 | 6 | 6 | 6（截断） | 6T | 1/T ✅ |
| 2 | 5 | 1 | 3 | 3T | 1/T ✅ |
| 4 | 8 | 2 | 6 | 6T | 1/T ✅ |

**这意味着：**

| 推论 | 价值 |
| :--- | :--- |
| 过载**不改变抽牌速率** | 玩家不会因为过载"变穷" |
| 攒牌**没有额外收益** | 消除了"憋牌刷牌库"的最优解 |
| **调参自由** | 改 T、改上限、改初始张数，都自动约掉，只需调节奏感 |

### 2.6 实测验证

T=3s，S=3，U=6，D=1，180 秒窗口：

| 玩法 | 过载次数 | 抽牌总数 | 重抽量 |
| :--- | :---: | :---: | :---: |
| 憋牌不出 | 10 | **61** | 恒为 4 |
| 慢出牌 6s | 5 | **60** | 恒为 4 |
| 正常出牌 3s | 0 | **60** | — |
| 快出牌 2s | 0 | **60** | — |

**四种极端玩法抽牌量几乎完全相同（61 vs 60，差异来自模拟窗口的边界效应）。**

当 D=3（卡牌效果抽 3）：

| 玩法 | 过载次数 | 抽牌总数 | 重抽量 |
| :--- | :---: | :---: | :---: |
| 憋牌不出 | 10 | 63 | 恒为 6 |
| 正常 3s | 0 | 63 | — |

**中性在 D≠1 时同样成立。**

### 2.7 过载真正的代价

> **不在于抽得慢，而在于手牌清零。**

你攒了 6 张、等着一张关键卡，一口气全没了。**它惩罚的是"手里囤着不用的战术选择"，不是"抽牌效率"。**

**这是纯事件性的压力，不是惩罚性机制。** 玩家不会被数值惩罚，只会被剥夺"囤积"这个选项。

### 2.8 UI 要求

| 要求 | 说明 |
| :--- | :--- |
| 过载时必须有明显提示 | 屏幕特效 + 文字「过载」 |
| 显示本次重抽张数 | 让玩家知道"我会抽 4 张"，而不是黑箱 |
| 手牌接近上限时有预警 | 第 5、6 张时有视觉提示 |
| 不能遮挡弹幕 | 手牌区域放在屏幕下方边缘 |

## 三、能量系统

### 3.1 参数

| 参数 | 值 | 符号 |
| :--- | :---: | :---: |
| 能量上限 | **3** | E |
| 回复间隔 | **T = 5.0s**（与抽牌间隔相同，全难度固定） | T |
| 每幕开局能量 | **充满（= E）** | — |
| 主动卡消耗 | 1–3 点 | — |

> **注意：能量与符卡的重置规则不同。**
> 能量**每幕开头回满**（见 3.6），符卡**只在损失残机时重置**（见第六节）。
> 这两条不能混淆——能量是"每幕重新起跑"，符卡是"用命换来的补充"。

### 3.2 规则

```
能量回复计时（每帧）：

  若 能量 < E：
      ├─ 计时器 += dt
      └─ 若 计时器 >= T：
            ├─ 能量 += 1
            └─ 计时器 = 0
  否则（能量已满）：
      └─ 计时器 = 0        ← 满能量时不计时、不累积
```

**注意：** 计时器在能量满时清零，不累积。这一点必须明确，否则玩家会以为"满了之后还在攒"。

### 3.3 两个关键的结构性质

#### 性质一：能量与手牌共用同一个 T，严格 1:1

```
能量速率 = 1 点 / T
抽牌速率 = 1 张 / T
→ 每抽到 1 张牌，正好得到 1 点能量
```

**这不是巧合，是两个系统共用同一个时间基准的必然结果。**

#### 性质二：过载不破坏这个比例

```
过载：抽 R 张，停顿 (R-1) × T 秒
      停顿期间能量回复 = (R-1) × T / T = R-1 点
=>    R 张牌 : R-1 点能量   ← 牌略多于能量，是过载的小赚
```

**过载是双重中性的**：既不影响抽牌速率，也不影响能量配比。它只改变手牌内容。

### 3.4 过载停顿期间，能量照常回复

> **过载停的是"抽牌"，不是"时间"。能量计时照常走。**

**理由：** 规则定义的是"每隔抽一张牌的时间回复一点能量"——这是**时间驱动**的，不是抽牌驱动的。既然停的是抽牌事件，能量就不该停。

**收益：**

| 收益 | 说明 |
| :--- | :--- |
| 逻辑一致 | 停顿只作用于抽牌这一个系统 |
| 避免隐性浪费 | 否则满能量时过载会白白丢掉 (R-1)×T 秒的回能 |
| 形成节奏起伏 | 过载后短暂"有能量没牌"，随即新牌到来 |

### 3.5 满能量 + 满手牌是最差组合（设计意图）

| 状态 | 后果 |
| :--- | :--- |
| 能量满 | 停止回复，时间被浪费 |
| 手牌满 | 下次抽牌即过载，手牌清零 |
| **两者同时** | **双重浪费** |

**这是有意的"贪心惩罚"**：攒着不用 = 亏。它和过载的"手牌清零"共同构成同一个压力：**鼓励玩家持续出牌。**

### 3.6 每一幕开局：满能量 + 初始 3 张手牌

| 项 | 值 |
| :--- | :--- |
| 能量 | **充满（3/3）** |
| 手牌 | **3 张（= 初始手牌数）** |

**效果：**

| 效应 | 说明 |
| :--- | :--- |
| 每幕都有一次"白送的爆发窗口" | 玩家可以一开场就打出一张高费卡 |
| 三幕节奏感明确 | 每一幕都是一次"满能量起跑" |
| 世界观自洽 | 进入新一层信息层，自机的灵力被重置 |

### 3.7 平均卡费决定出牌频率

因为牌与能量是 1:1，长期可出牌量完全由平均卡费决定：

| 平均卡费 | 90 秒内最多出牌（T=3s，上限 3） |
| :---: | :---: |
| 1.0 | 33 张 |
| 1.5 | 22 张 |
| 2.0 | 16 张 |
| 2.5 | 13 张 |
| 3.0 | 11 张 |

> **平均卡费就是出牌频率的旋钮。** 想让玩家更频繁出牌就压低均价，想让每次出牌更有分量就抬高均价。这个关系是线性的，极好调。

### 3.8 选卡与出牌

- **C 键循环**选中手牌中的某一张
- **Z 键打出**当前选中的那张
- 能量不足时 Z 无效，需有明确反馈（音效 + 高亮闪烁）

### 3.9 初始卡组

玩家开局携带一个**初始主动卡卡组**（具体张数待平衡）：

| 卡 | 效果 | 能量 |
| :--- | :--- | :---: |
| 待定 | 待定 | 待定 |

**注意**：初始卡组里应包含**至少 1 张保命卡**（清弹或无敌），保证零构筑时也有应对手段。

### 3.10 UI 要求

| 要求 | 说明 |
| :--- | :--- |
| 能量分段显示 | 3 格，满格点亮 |
| 下一格的回能进度 | 环形或条状进度，让玩家知道还差多久 |
| 能量不足时出牌 | 选中卡高亮闪烁 + 失败音效，不消耗任何东西 |
| 满能量提示 | 视觉上明确"已满"，避免玩家误以为还在攒 |

## 四、四幕结构

> **2026-10-26 调整：三幕改为四幕，对齐《杀戮尖塔》的主线结构。贝子移至第四幕，定位相当于"心脏"。**

| 幕 | 场景 | 信息层 | 道中结构 | 关底 BOSS | 交易内容 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **第一幕** | 塔外 | 流言 | 4 普通 + 1 精英 + 道中BOSS + 2 普通 + 3 精英 | **真千亦** | 被动卡 + 基本内容 |
| **第二幕** | 塔内 | 影像 | 同第一幕 | `Boss_Act2`（占位） | 卡牌 + 删卡 + 基本内容 |
| **第三幕** | 塔内 | 伪真 | 同第一幕 | `Boss_Act3`（占位） | 卡牌 + 删卡 + 基本内容 |
| **第四幕** | 塔内顶层 | — | **1 精英 + 道中BOSS + 商店** | **渡里贝子（心脏位）** | 战前最后一次总决算 |

### 4.1 第四幕的特殊结构

```
1 精英 → 道中BOSS → 商店 → 贝子
```

| 设计意图 | 说明 |
| :--- | :--- |
| **短道中、长 BOSS** | 前面只用来"热手"与攒钱，重量全压在贝子身上 |
| **商店在贝子之前** | 最后一次调整构筑的机会——玩家会把攒的钱全花掉、把牌组精简到最优，然后挑战 |
| **情绪价值** | 与《杀戮尖塔》心脏前的商店同构，让玩家在最终战前做一次"总决算" |

### 4.2 时长核算

| 幕 | 时长 |
| :--- | ---: |
| 第一至三幕（各约 286s） | 858s |
| 第四幕（约 372s） | 372s |
| **合计** | **≈ 1230s = 20.5 分钟** |

**关底 BOSS 时长是本估算的关键**，参照东方正作的实测结构：

| BOSS 类型 | 构成 | 时长 |
| :--- | :--- | ---: |
| 3 面 BOSS | 非符 2 + 符卡 3（各 40–60s 计时，按 65% 完成度） | 110–140s |
| 6 面 BOSS | 非符 3 + 符卡 5–6 | **250–310s（4–5 分钟）** |

> ⚠️ **早期估算曾把关底 BOSS 记为 90–100 秒，低估约 3 倍。** 实际正作的符卡有独立计时上限，一个 6 面 BOSS 的完整流程是 4–5 分钟。

### 4.2b 符卡系统（X 键 · Bomb）

> **2026-10-26 新增。** 早期版本曾把 Bomb 砍掉、并入主动卡，**这个判断是错的**，已撤销。
>
> 原因：主动卡要「抽到 + 选中 + 有能量」三重条件，而 Bomb 只需要一个键。
> **紧急情况下的可用性差一个数量级**——没有它，玩家在密集弹幕下没有任何救场手段。

#### 基础规则（参照东方正作）

| 项 | 规则 |
| :--- | :--- |
| 触发键 | **X** |
| 初始符卡数 | **3**（与绀珠传 Legacy 一致：`初期プレイヤー数は3で、ボム数は3個`） |
| **重置时机** | **仅在损失残机时**重置为初始值 |
| 每幕开局 | ❌ **不回满**（与能量不同） |
| 恢复方式 | 商店购买 / 部分卡牌效果 |
| 释放效果 | 清屏 + 无敌 + 可移动 |
| 消耗 | 1 张 |

> **⚠️ 关键区别：符卡不是每幕回满的。**
> 正作中符卡只在 miss 时重置，这是「用命换补充」的设计。
> 若每幕回满，符卡就失去稀缺性，玩家会当成每幕三次免费清屏。

#### 释放效果

| 参数 | 值 | 说明 |
| :--- | :---: | :--- |
| 清屏半径 | **全屏** | 所有敌弹立即消失 |
| 无敌时长 | **2.0 秒** | 期间闪光、可移动、可射击 |
| 对敌伤害 | **0**（默认） | 可通过被动卡改造 |
| 释放瞬间 | 屏幕白闪 + 自机图形爆发 | 必须给足反馈 |

#### 决死系统（Deathbomb）

> 参照永夜抄的公式，配合绀珠传的「普通炸弹 + 一定决死时间」。

| 参数 | 值 | 依据 |
| :--- | :---: | :--- |
| **基础决死时间** | **8 帧** | 各作通行固定值 |
| **每张符卡加成** | **+6 帧** | 沿用永夜抄 `BOMB数 × 6` |
| **上限** | **30 帧** | 沿用永夜抄上限 |
| **符卡为 0 时** | **4 帧** | 仍给反应时间，但基本救不回 |
| **BOSS 符卡战中** | **×2** | 沿用永夜抄惯例 |

**换算（60 帧 = 1 秒）：**

| 符卡数 | 决死帧数 | 换算 | 体感 |
| :---: | :---: | :---: | :--- |
| 3 | 8 + 18 = **26** | ≈0.43 秒 | 很宽裕 |
| 2 | 8 + 12 = 20 | ≈0.33 秒 | 够用 |
| 1 | 8 + 6 = 14 | ≈0.23 秒 | 紧张 |
| 0 | **4** | ≈0.07 秒 | 基本救不回 |

**设计效果：**

> **手里有符卡本身就是免疫力。** 用掉一张，下次中弹的容错时间就少 6 帧。
> 这比「符卡=炸弹」多一层策略：**你是在用未来的容错，换现在的清屏。**

#### 决死期间的行为

| 项 | 规则 |
| :--- | :--- |
| 自机移动 | **冻结**（正作就是冻结的，这是紧张感来源） |
| 自机射击 | 停止 |
| 屏幕表现 | 轻微抖动 / 去色 / 时间感变慢 |
| 按 X 成功 | 进入 Bomb 无敌，**不进 MISS** |
| 没按 | 扣残机，符卡重置为 3 |

#### 符卡数据化（为被动卡改造留接口）

```json
{
  "id": "spell_default",
  "name": "符片解放",
  "clearRadius": 9999,
  "invulnTime": 2.0,
  "damage": 0,
  "freezeTime": 0,
  "extraEffects": []
}
```

**被动卡可以修改它**（方案 B：改变形态，不只是加数值）：

| 卡类型 | 效果 |
| :--- | :--- |
| 广域符卡 | `invulnTime` +1 秒 |
| 破邪符卡 | 释放时对全场敌人造成 `damage: 400` |
| 迟缓符卡 | 释放后敌弹 `freezeTime: 2.0` 秒 |
| 续符 | 消耗后 50% 概率不扣 |
| 扩容符卡 | 符卡槽上限 +1（同时延长决死时间） |

**至此，被动卡能改造四种对象：**

```
① 射击形态（ShotProfile）
② 元素属性
③ 经济（掉落、价格）
④ 符卡（本系统）
```

## 四之二、关卡生成：种子驱动的随机关卡

> **2026-10-26 新增。** 道中波次、掉落卡牌、商店选项全部按种子生成。

### 4.7 核心原则：只随机内容，节奏固定

| 固定（不随机） | 随机（按种子） |
| :--- | :--- |
| 每幕的**总波数** | 每一波用哪些敌人 |
| 每幕的**精英波数量** | 每一波内的敌人配比 |
| 波次的**前后顺序结构** | 掉落的卡（3 选 1） |
| | 商店的 8 件商品 |

**为什么节奏必须固定**：若波数也随机，一局可能只有 2 波精英（钱太少、构筑不起来），也可能 6 波（钱多到失衡）。**节奏必须可控，内容才随机。**

### 4.8 结构化种子派生

```
masterSeed
  ├─ derive(masterSeed, "stage", act)   → 波次编排
  ├─ derive(masterSeed, "reward")       → 掉落与商店
  └─ derive(masterSeed, "cards")        → 抽牌堆洗牌顺序
```

**派生方式**：`masterSeed + 字符串标签` 哈希出子种子。

| 收益 | 说明 |
| :--- | :--- |
| 三个系统互不污染 | 调波次生成不会影响抽卡顺序 |
| 可单独重放 | 想复现某一幕的波次，不需要跑完整局 |
| bug 可精确定位 | "种子 8842 第二幕的商店" 就够了 |

### 4.9 生成后校验（必须实现）

| 校验 | 规则 | 不通过的后果 |
| :--- | :--- | :--- |
| **经济可达性** | 本幕可获得的蜃銭 ≥ 一张卡的最低价格 | 玩家可能"钱不够，什么都买不起" |
| **波次完整性** | 生成的波次数量 = 预设值 | 死循环或卡关 |
| **敌人池非空** | 每一波至少有 1 种可选敌人 | 空波次 |

> **失败时不是报错崩溃，而是用种子重新生成（带重试上限）。**

### 4.10 玩家可见性（三条便宜但重要）

| 要求 | 位置 |
| :--- | :--- |
| 本幕波次构成预览 | 关卡开始前：`3 普通 / 1 精英 / 道中 / 2 普通 / 2 精英` |
| 商店前的剩余钱数提示 | 进入商店时 |
| **种子号显示** | 暂停菜单（方便报 bug，也方便玩家分享） |

**这三条不花钱，但能让玩家感觉"局面是可控的"。**

### 4.11 成本

| 项 | 工作量 |
| :--- | :--- |
| 波次生成器 | 约 200 行 |
| 种子派生 | 约 50 行 |
| 生成后校验 | 约 80 行 |
| 测试 | 种子复现、合法性、经济可达性 |
| **合计** | **约 1.5–2 天** |

**在 P3 流程阶段实现**，不影响 P0 开工。

## 五、难度

### 5.1 核心约束：T 全难度固定为 3 秒

> **抽牌间隔与能量回复间隔共用同一个 T = 5.0s，且不随难度变化。**

这是 2026-10-26 的决定。理由与后果：

| 项 | 说明 |
| :--- | :--- |
| **好处一** | 自机侧节奏参数全难度一致，**只需一套平衡数值** |
| **好处二** | 难度差异集中在三处可调表（弹幕密度、符卡、经济），实现与测试更简单 |
| **好处三** | 跨难度分数可比（起跑资源相同） |
| **代价** | 失去「难度双轴」这个卖点（见 5.5 的替代框架，待验证） |

### 5.2 难度表

> **所有难度：初始资源完全一致，难度差异来自三条轴。**

| 参数 | 值 | 是否随难度变化 |
| :--- | :---: | :---: |
| 抽牌间隔 T | **5.0s** | ❌ 不变 |
| 能量上限 | 3 | ❌ 不变 |
| 能量回复间隔 | **5.0s**（= T） | ❌ 不变 |
| 初始手牌 / 上限 | 3 / 6 | ❌ 不变 |
| 初始卡组 | 相同 | ❌ 不变 |
| **初始残机** | **3** | ❌ **不变** |
| **弹幕密度** | 低 → 极高 | ✅ 变化 |
| **BOSS 符卡** | 变化 | ✅ 变化 |
| **卡牌价格** | 低 → 高 | ✅ **变化** |
| **怪物掉落蜃銭** | 多 → 少 | ✅ **变化** |

### 5.3 第二条轴：经济

**2026-10-26 决定：初始残机全难度统一为 3，难度的高低通过「卡牌价格」与「怪物掉落金币数量」来调节。**

| 难度 | 掉落蜃銭 | 卡牌价格 | 净效果 |
| :--- | :---: | :---: | :--- |
| Easy | 多 | 低 | 买得起更多符片与残机，构筑宽松 |
| Normal | 中 | 中 | 基准 |
| Hard | 少 | 高 | 每次购买都要取舍 |
| Lunatic | 最少 | 最高 | 构筑极度受限，必须精准取舍 |

**这条轴的设计价值：**

| 价值 | 说明 |
| :--- | :--- |
| 与东方正作逻辑一致 | 起跑线相同，高难度的资源更稀缺 |
| 惩罚"手滑"而非"卖血" | 残机不直接扣，但每次死亡的经济损失在高难度下更痛 |
| 让商店有难度意义 | 同一个商店界面，在不同难度下是完全不同的决策压力 |
| **调参极便宜** | 只改两张数值表（价格、掉落），不动任何代码逻辑 |

### 5.4 三条轴（完整视图）

```
① 弹幕密度   —— 玩家要躲什么
② BOSS 符卡  —— 玩家要面对什么机制
③ 经济       —— 玩家能构筑成什么样
```

> **三条轴共同决定难度，但都不改变玩家的「基础工具箱」**（3 残机、T=3s、能量 3、手牌 6）。
> 玩家在每一档难度下的**起跑线完全相同**，差别在于**跑道上有什么**和**路上能捡到什么**。

### 5.5 一个值得验证的效果（未验证）

因为初始资源一致，难度压力全部来自"面对的敌人"与"能买到的资源"：

| 难度 | 同样的卡组会怎样 |
| :--- | :--- |
| Easy | 弹幕稀疏且钱多 → 防御型卡价值低，输出型卡通吃 |
| Lunatic | 弹幕极密且钱少 → 防御型卡价值暴涨，纯输出构筑可能活不下去 |

**同一个牌池，在不同的压力与预算下，最优构筑会自然分化。** 这不是靠数值调出来的，是环境差异逼出来的。

> ⚠️ **这是设计意图，不是已验证的结论。** 必须在 P4 平衡阶段实测。**实测不成立就不得写进 README 或宣传材料。**
