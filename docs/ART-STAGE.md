## 一、四幕背景：不是四张图，是四套可滚动的图层

东方正作的背景会随推进滚动。做法是若干张**纵向无缝循环**的贴图，各自以不同速度下滚，叠出纵深。

所以每幕产出 **3 张 tile**：

| 层 | 文件名 | 滚动速度 | 内容 |
| :--- | :--- | ---: | :--- |
| 远景 | `act{N}_far.png` | 0.0–0.22 | 天空、远山、云海、塔内巨构 |
| 中景 | `act{N}_mid.png` | 0.26–0.45 | 杉林、符札残片、长带云、檐角 |
| 近景 | `act{N}_near.png` | 0.72–0.85 | 雾、飞掠的碎云、光尘 |

**尺寸：384×768，纵向无缝。** 视窗是 384×448（与 `src/core/world.ts` 的 `FIELD_W/FIELD_H` 一致），tile 比视窗高约 1.7 倍，滚一圈约 1.7 屏才重复。

> 第一幕与第四幕的**远景速度是 0**：真实飞行里天空是静止的，只有地形和云在动。

### 命令

```bash
pnpm art:stage      # 只重出四幕背景
pnpm art:ui         # 只重出 UI
pnpm art:all        # 全部（卡面 + 背景 + UI）
```

## 二、四幕的视觉设计

统一原则（这条比任何单张图都重要）：**明亮只放在上部/远处，战斗区始终压暗。**

| 幕 | 场景 | 信息层 | 主色 | 关键视觉 |
| :--- | :--- | :--- | :--- | :--- |
| 一 | 塔外 | **流言** | 黄昏橙 / 靛蓝 | 夕阳压地平线，层叠山脊，塔的蜃景悬在山脊之上；杉林与乱流暗示怪物涌出 |
| 二 | 塔内 | **影像** | 冷青 / 蓝紫 | 竖井巨柱、连续尖拱、深处的信息核心；横向错位的半透明重影 |
| 三 | 塔内深处 | **伪真** | 紫红 / 暗品红 | 与二幕同构但**镜像反转、左右柱比例失衡**；核心更大更偏红；成对的"孪生"残片 |
| 四 | 塔顶 | **剥落** | 夜蓝 / 暖金 | 云海在地平线以下被照亮，光柱自云下打上来；信息残片骤减到近乎为零 |

**「信息层」是四幕的质变点**，不是单纯的"更暗一点"：从密集流言 → 影像重影 → 镜像伪真 → 彻底剥落。玩家会觉得"这地方变了"，而不只是"变暗了"。

### 科技感 vs 幻想乡

科技感来自**「信息」而非「机械」**：用青海波、七宝、麻叶这些和风纹样承载信息流。这些纹样既属于幻想乡，本身又是"被反复复制传播的图案"——正好是信息。

刻意避开了赛博朋克符号（霓虹方框、电路线、扫描线），那些是外界视觉，放进幻想乡会违和。

## 三、弹幕可读性：静止覆盖层是硬约束

这是整套方案里**最容易做错、也最关键**的一点。

### 不能把压暗画进滚动图层

图层会滚动，暗区会跟着跑走，压不住任何东西——玩家躲弹时不会因为"刚好滚到亮的地方"而看不清子弹。

### 正确做法

压暗必须是**静止的覆盖层**，固定贴在视窗上。见 `stage_build.py` 的 `make_static_overlay()`：

| 幕 | 压暗起点 | 最大不透明度 |
| :--- | ---: | ---: |
| 一 | 0.36 | 0.62 |
| 二 | 0.30 | 0.22 |
| 三 | 0.30 | 0.24 |
| 四 | 0.30 | 0.50 |

一、四幕背景本身很亮，才需要压；二、三幕本来就暗，压 0.3 以上就是把画面糊死。

`_acts_preview.png` 里每幕都有**「纯背景 / 叠弹幕」对照**，右边那张才是决定成败的——占了位弹幕还能看清，才算过关。

### 设计约束

- 与四幕共用同一套调色板（`CYAN` / `VIOLET` / `GOLD` …），避免 UI 和场景割裂
- 和风元素：青海波的装饰带、四角内折角饰、符札形、方孔铜钱
- 光效一律用**加法叠加**，不要用 alpha 合成（后者会压暗底下的场景）

## 五、接入游戏

### 背景（滚动视差）

PixiJS 侧需要三个 `TilingSprite`（每层一个），按 act 切换纹理，每帧递增 `tilePosition.y`：

```ts
// 伪代码
layers.forEach((sprite, i) => {
  sprite.tilePosition.y += scrollSpeed[i] * dt;   // 远景 0，中景 0.30，近景 0.75
});
```

**接缝要求：** `TilingSprite` 的 pattern 必须上下可循环——本生成器已保证（`_seam_check.png` 可自检）。

### 静止覆盖层

`make_static_overlay()` 的输出是一张 384×448 的渐变 RGBA，做成一个**固定在视窗最上层**的 Sprite（在弹幕层之下、自机之上或之下都行，但必须在背景之上）。切幕时换掉它。

### UI

面板框走 9-slice；能量格/符卡槽/金币按状态切图；进度条用 `progress_fill` 按比例裁切宽度。

## 六、踩过的坑（改这些文件前先读）

| 坑 | 症状 | 原因 / 解法 |
| :--- | :--- | :--- |
| 相位算错 | 渐变完全错位，黄昏带跑到视窗外 | 周期渐变必须按 `(y - PAD) % RH` 算相位，不能用 `linspace(0,1,n)` 铺满整张画布 |
| 山脊填充过深 | 天空整块消失，只剩山 | 填充只到**本周期末尾**，不能超一个周期，否则包裹副本互相覆盖 |
| 加色不记覆盖度 | 中/近景层的光效全部消失 | `commit(add)` 也必须累加 `cov`，否则透明底上 alpha=0 |
| 用 alpha 合成 mid/near | 二、三幕糊成黑 | 这两层是黑底光效，要用**加法叠加**；深色剪影都画在 far 层 |
| 按 RH 铺构图 | 地平线、太阳落到视窗外 | 构图比例按 `VIS_H`（可见窗口）算，用 `stageart.V()` |
| 角饰压字 | 面板首行文字被横线划掉 | 角饰缩进内圈，或把面板加高让内容下移 |
